Privacy boundary

Local-first does not mean “nothing ever leaves the machine.”

Meditate keeps inspection, filtering, validation, reports, and archives local. Planning sends current directive text and a bounded selection of locally secret-scanned and redacted evidence to the pinned Anthropic model.

In plain language

No product telemetry does not mean no network transmission.

There is no Meditate account, telemetry collector, analytics endpoint, or remote memory store. However, plan and run deliberately invoke Anthropic with user-derived content after local filtering.

meditate inspect is entirely local and makes no model call. meditate plan and meditate run invoke the explicitly configured Anthropic model only when local preflight finds a consolidation candidate; a stable no-op makes zero calls. They never silently select a different provider or model.

meditate decide transmits the frozen parent context and exact selected archived option or byte-preserved custom response, plus bounded decision lineage, to Anthropic instead of transmitting newly appended live history. Anthropic's response becomes a fresh read-only successor plan. The input is recorded as operator-asserted user authority, but identity is not authenticated or attested, and Meditate cannot prove that an invoking agent faithfully relayed the user's real answer. meditate decide rejects a recognized high-confidence secret shape in a custom response before submission. Other option/custom text remains user-derived and is not anonymous or risk-free.

What the CLI may read

Only configured sources are eligible:

  • allowlisted Claude Code and Codex instruction files;
  • Claude and Codex prompt indexes and, when explicitly enabled, bounded transcript records;
  • agent auto-memory or configured memory files;
  • active Kindex constraints, directives, decisions, and related provenance when Kindex is enabled.

Histories, transcripts, auto-memory, and Kindex are read-only evidence. Meditate writes only the instruction targets named in the configuration.

What can be sent to a model

Before any provider call, records are streamed through local parsing, deduplication, secret detection, redaction, deterministic ranking, temporal-breadth selection, and hard size/token limits. High-confidence secret-bearing records are excluded wholesale rather than sent with a replacement token.

The Anthropic request contains a system prompt, a constrained JSON output schema, and a canonical JSON packet. That packet contains:

  • the configured target path labels and hashes, mutable candidate directive IDs/text/metadata, and bounded related immutable context after local secret scanning/redaction; non-candidate directive IDs are not sent to the planner;
  • selected evidence records in oldest-to-newest order, including their stable IDs, timestamps, source/authority metadata, scoring fields, and locally redacted text;
  • the authority/comparison rules, allowed destination targets, bounded overlap candidates, and parser-degradation state.

Unselected history records and records excluded for high-confidence secret shapes are not included in the request. The model still receives user-derived instruction and interaction text; “redacted” is a transformation with limits, not a claim that the transmitted content is anonymous or risk-free.

Behavioral verification transmission

meditate verify is a separate model-backed operation. It sends owner-authored neutral probe/counter-probe scenarios with opaque case references and, for predecessor and candidate conditions, the complete archived instruction bundle to the selected local Claude or Codex CLI. Private action IDs, literal detector phrases, case descriptions, and required/forbidden/order assertions are not sent to the consumer. That CLI may transmit the material to its configured provider under the CLI’s own account and retention settings. The consolidation planner never receives the suite or verifier outcomes. Suite files are rejected when they contain a recognized high-confidence secret shape, but they remain user-authored content and are not anonymous. Codex verification replaces ambient CODEX_HOME with a fresh private directory, ignores user config and rules, and requires OPENAI_API_KEY; this keeps global AGENTS.md, memories, and configuration out of the control condition. The frozen suite and verification receipt are private local artifacts.

Credentials

API keys are read at runtime from standard provider environment variables. Anthropic planning uses ANTHROPIC_API_KEY; clean-room Codex verification uses OPENAI_API_KEY. Their values are not written to plans, reports, or archives.

Local storage

plan.json, manifest.json, evidence.json, frozen verification-suite.json, verification.json, and run-specific JSON/Markdown reports are private local plan artifacts. Reports and JSONL summaries default to the operator’s XDG state directory; recoverable run archives default to the XDG data directory. Meditate requires private directory/file modes for this material and refuses unsafe state roots. Depending on the run, these artifacts contain the current decision request or bounded collision scope, the exact selected/custom response, private verifier assertions and detector phrases, derived verifier actions, and lineage. The append-only JSONL is summary-only: it retains request IDs, choice keys, hashes, and lineage depth, never the raw question, options, or custom response.

Archive deletion is preview-only unless an exact run ID and --execute are supplied. Active recovery material requires an additional --force. During successor purge, its exact run-ID JSON and Markdown reports are deleted. The replay tombstone/marker retains only IDs and hashes; it does not retain raw response text. The append-only summary likewise retains only parent, request, and successor IDs, the conflict fingerprint, and plan/response hashes needed to prevent replay. A retained parent still contains its own archived question until separately purged. The tombstone also distinguishes explicit erasure from missing or corrupt state.

Telemetry and the documentation site

The Meditate CLI contains no product telemetry. This documentation site is a set of static files: it sets no cookies and loads no third-party fonts, scripts, images, or analytics. Because it is hosted by GitHub Pages, GitHub may process ordinary web-server request information under GitHub’s own privacy terms.

Operator responsibility

The operator chooses the evidence sources, model provider, model ID, token budgets, retention period, writable targets, and whether a reviewed proposal is applied. Operators should review their model provider’s data-handling terms and avoid enabling transcript bodies unless the additional evidence is proportionate to the task.

Questions and changes

Privacy-affecting changes should be raised in the project issue tracker. The source version of this policy is available as PRIVACY.md.
